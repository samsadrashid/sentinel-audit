# M3 scope and conditions (approved 2026-11-09)

Recorded as append-only decisions **D-58** (scope, acceptance, mandatory conditions), **D-59** (provisional domain identities), **D-60** (acquisition), **D-61** (Grype input), **D-62** (scanner overlap) and **D-63** (fixtures and thresholds). The proposal is in `docs/m3/scope-proposal.md`.

| Deliverable | Implementation |
|---|---|
| Domain modules D01 Web, D02 API, D08 Backend, D14 Database (provisional, D-59) | `src/sentinel/domains/`: applicability, finding-to-domain mapping, per-domain coverage. Independent rules in `src/sentinel/rules/semgrep/D01.yaml`, `D02.yaml`, `D08.yaml` and `D14.yaml`, all hash-pinned with the core rules (`SEMGREP_RULE_PINS`). An extra or changed rule file is `NOT_RUN` |
| Trivy, Checkov, Grype adapters | `src/sentinel/adapters/scanners.py`. Trivy (S2): offline, `--skip-db-update --skip-java-db-update --skip-check-update --offline-scan`. Checkov (S1): only where IaC or container files exist, `--skip-download`. Grype (S2): the Syft SBOM on stdin, otherwise a recorded `directory_fallback` (D-61); no auto-update. All run in rootless Podman, by digest |
| D-29 snapshots | `osv_database`, `trivy_database` and `grype_database` policy pins: manifest SHA-256 plus every file's hash, verified before each run. Snapshots used are listed in `reproducibility.snapshots` and in the run manifest's `vulnerability_db_snapshots`. Any database-backed check that didn't run on a pinned, verified snapshot makes the run `non_reproducible` and is never `PASS` |
| Deduplication with provenance (D-62) | Dependency findings share a scanner-independent identity: package plus canonical advisory (smallest CVE alias, else GHSA). Each finding's `sources` lists every contributing scanner, its own rule, its evidence and its database snapshot |
| Fixtures (D-63) | `tests/fixtures/domains/<domain>/vuln-01..10` and `clean-01..10`, generated by `scripts/m3/make_fixtures.py`. Expected issues and their designated checks are declared before measurement |
| Measurement (E6) | `scripts/m3/measure.py`: real scanners through the orchestrator; per-domain recall, false positives, and validated checks. **Coverage is claimed only for validated checks** (`src/sentinel/domains/coverage.json`, written by the harness; empty until the final real measurement) |

**Status:** the downloads in `docs/m3/acquisition-request.md` await owner approval (D-60). After installation, the real-scanner tests and the final measurement run, and the measured R and F proposal goes to the owner (D-63).
